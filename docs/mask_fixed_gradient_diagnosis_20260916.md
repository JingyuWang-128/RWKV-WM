# Mask 修复后裁剪原因诊断（2026-09-16）

## 范围与限制

只诊断，不启动训练、不修改优化器、不改变 weight=0.5，不调整既定准入门槛。
GPU 全被其他用户任务使用，本次使用 CPU。新增的两个脚本仅用于诊断。

- TwoRoom-W：preflight 第 200 步 latest.pt（不是失败点第 400 步的权重）。
- Action-Delay：preflight 第 800 步 latest.pt（不是失败点第 1000 步的权重）。
- 分项归因恢复 checkpoint 的训练采样 RNG；每批 4×8=32 个样本，两个固定批次。
- 同一 checkpoint/同一批数据测 H=1/5/10/20。长 H 是未完成课程模型的压力测试，
  **不是正式 H20 训练结果**，不能由此推断训练完的模型必然不稳定。
- 每项梯度均乘实际 loss 权重：factual/reference=1，effect=0.5，direction/magnitude=0.05。
- 不对梯度裁剪，直接测量原始梯度；分项向量相加后再计算总范数。

## 复现校验

| 更新 | 原 GPU 日志梯度范数 | 冻结 checkpoint + 相同样本的 CPU 重算 |
|---|---:|---:|
| TwoRoom-W step 201 | 2.1084406 | 2.1084449 |
| Action-Delay step 801 | 1.0454127 | 1.0454123 |

重算能复现这两个更新的剪裁前梯度。后续第二批仍使用相同冻结权重，不等于恢复训练
后的下一步梯度。所有归因结果只对诊断快照与样本成立。

## 日志趋势：不应将“门槛未通过”等同于“训练爆炸”

- TwoRoom-W step 201–300：裁剪率 97%，梯度中位数 2.0871。
- TwoRoom-W step 301–399：裁剪率 33.3%，梯度中位数 0.9226。
- TwoRoom-W 最后 50 步：裁剪率 28%，梯度中位数 0.8883。
- Action-Delay H5 失败窗口：裁剪率 22.5%，中位数 0.9056，最大值 1.424。
  该窗口无 scale<0.1 的严重裁剪，亦无 NaN/Inf。
- Action-Delay step600→800 固定 H20 验证 factual 从 0.4655 降至 0.4119，reference
  从 0.5203 降至 0.4581；因此不能称其因为裁剪而没有学习。

20% 是事先选择的工程门槛，不是理论证明的收敛条件。检查第 400/1000 步是否通过
与模型是否有学习能力是两个问题。本轮仍按 FAIL 记录，不追溯改成 PASS。

## 原因一：Action-Delay H5 是基础预测梯度叠加，非后三项主导

第一个固定批次，checkpoint step800、H5：

| 梯度来源 | 范数 |
|---|---:|
| factual | 0.42378 |
| reference | 0.62725 |
| 两者向量之和 | 1.04541 |
| 加权 effect | 7.0e-9 |
| 加权 direction | 0 |
| 加权 magnitude | 0 |
| 完整损失 | 1.04541 |

factual/reference 梯度高度同向。短期 action delay 的真实 effect 为零/很小，direction
与 magnitude 在此批次未激活。这次超限不是三项辅助 loss 导致；F4 在同一权重和样本
上移除它们也不会解除这次裁剪。第二个固定批次 H5 梯度为 0.69554，说明存在采样波动。
不能用这两个样本估计整体裁剪率，整体比例以上述实际训练窗口为准。

## 原因二：TwoRoom-W 的基础预测与 magnitude 都有贡献

第一个固定批次，checkpoint step200、H1：

| 梯度来源 | 范数 |
|---|---:|
| factual | 0.89258 |
| reference | 1.18037 |
| 两者向量之和 | 1.98746 |
| 加权 effect | 0.11005 |
| 加权 direction | 0.03436 |
| 加权 magnitude | 1.97318 |
| 完整损失 | 2.10844 |

各梯度存在抵消，不能把范数直接相加。去掉后三项后仍大于阈值 1。
H1 下约 89% 的总梯度平方范数集中在 world TimeMix，最后一层 key.weight 单个张量
约占 66%；同一批 H20 压力测试中该张量约占 78%。这定位了敏感参数，不证明该参数
实现有 bug，也不证明新增反事实分支没有间接影响。

同一固定批次的完整梯度范数 H1/5/10/20 分别为 2.108/13.889/17.222/19.912；
只保留 factual/reference 分别为 1.987/12.182/14.739/15.963。
因此这个早期 TwoRoom-W 快照确有多步梯度放大，且不是只去掉三项就能解决。

## 原因三：矩阵反传和 latent 自反馈共同贡献

在 TwoRoom-W 相同 checkpoint 的第一 microbatch（8 个样本）做路径归因。
仅诊断时 detach 特定路径，前向预测与损失保持完全一致，不更新参数。

| H20 反向路径 | 总梯度范数 |
|---|---:|
| 完整梯度 | 26.3404 |
| 仅切断跨步 latent 梯度 | 7.2565 |
| 仅切断跨步矩阵梯度 | 8.7480 |
| 切断矩阵与 shift 状态梯度 | 7.4324 |
| 同时切断 latent 与状态，只留局部反传 | 2.6917 |

两条路径都有明显贡献，但这是改变梯度图的归因，不是可直接采用的稳定化方案，也不是
对 Jacobian 指数增长的证明。矩阵切断还移除了起点真实历史的梯度，不能把差异全归因于
未来 20 步。即使只留局部梯度仍超过 1，说明不能仅用“长程递推爆炸”解释全部裁剪。

额外无梯度观察：该批次 H20 时各层归一化前 key 向量范数最小值均大于约 0.066，
远离 1e-12 epsilon；没有证据支持 key 归一化分母触及 epsilon 是这次主要原因。

## 解决/缓解建议（未实施）

1. 保持权重 0.5、mask 修复和原公式，先做较长 H1 的受控诊断；当前在 TwoRoom-W
   梯度正在下降时因固定 200 步窗口退出，尚不知道是否会自然稳定。建议诊断观察至
   1000–2000 步，并保留严重异常 fail-fast；这是新的诊断协议，不修改本轮 FAIL。
   正式阶段仍不得在原门槛未满足时启动。
2. 对正式 F3/F4 使用预试验确定的共同课程/学习率安排；可测试 H1→2→5→10→20，
   给短程动力学足够学习时间。不能独立改变两组预算后将差异全部归因于辅助损失。
3. 若长程放大持续存在，优先针对 TimeMix key/readout 及 latent 反馈的敏感性做
   初始化尺度、参数组学习率、谱增益约束等单因素对照。参数组 LR 只能影响后续轨迹，
   不会直接降低当前原始梯度。谱约束若改到官方 RWKV 核心，需要单独标记为结构变化，
   不能宣称仍完全等同官方实现。不能单凭低 action 参数梯度就排除 action 的前向作用。
4. 若修改损失获得授权，可用有尺度下限的 magnitude 目标替换当前 log(norm+eps)，
   如对 log(1+||effect||²/s²) 的差使用 Smooth-L1；其局部导数有界于常数 1/s。
   这是候选损失，不保证全部参数梯度有界；s 只用训练集固定统计，不使用预测范数作为
   除数。当前 F3 原公式暂不修改，F4 不被偷换为这种新目标。
5. 不靠整体缩小 loss、提高 clip threshold 或永久 detach 来制造低裁剪率。
   若要讨论新门槛，必须事先记录并同时考虑缩放程度、验证质量、梯度随 H 的增长，
   而不是把 22.5% 的轻裁剪与极端梯度爆炸等同。

无法保证这些候选措施不影响精度；必须以原空间固定 H20 验证、effect 评价与鲁棒性
对照验证。当前根因已定位到上述损失/路径/参数层面，但尚未验证哪种修复最有效。
