 # 长程任务方法与实验规范

## 1. 目的

本文档定义本项目中“长程任务能力”“长程规划”“时间抽象”和“长开环
执行”的可检验含义，并规定后续方法修改、基线比较、指标统计和资源调度的
最低要求。

现有 Two-Room CRAFT Phase-B 结果只能证明：在最多 50 个环境动作的预算内，
长程可达性度量配合 5/10 步短窗口闭环控制，提高了对较大
`goal_offset` 目标图像的到达率。它不能单独证明 CRAFT 已学会可靠的长动作
预测、有效的多尺度执行或更少的规划次数。

在完成本文档要求的控制实验之前，对外应使用“远期目标图像条件下的长程
闭环到达能力改善”，不应使用“已经解决长程规划”或“能够稳定开环执行
百步计划”等表述。

## 2. 必须区分的概念

### 2.1 任务内在长度 `H*`

`H*` 是完成任务所需的最少或接近最少的真实环境动作数。真正的长程任务应
具有较大的 `H*`，例如 100、200、500 或 1000，而不是仅仅让演示轨迹中的
起点和目标相隔很远。

### 2.2 `goal_offset`

`goal_offset=k` 只表示目标图像来自同一数据轨迹中起点后的第 `k` 个时间步。
它不等于：

- 任务最少需要 `k` 个动作；
- 规划器一次预测 `k` 个动作；
- 控制器执行 `k` 个动作后才重新规划；
- 在线评测预算为 `k`。

因此，`goal_offset` 只能作为远期目标的代理难度，不能独立作为真实任务长度。

### 2.3 规划长度、承诺长度与任务预算

- **规划长度**：一次优化时想象的动作长度。
- **承诺长度**：一次规划后实际连续执行多少动作才允许重新规划。
- **高层规划次数**：产生路线、子目标、技能或 option 的昂贵决策次数。
- **低层控制次数**：根据新观测进行局部反馈纠偏的次数。
- **任务预算**：整个 episode 最多允许执行的环境动作数。

论文和报告必须分别记录这些量，不能用“步数”笼统代替。

### 2.4 三种不同的长程能力

1. **长程任务能力（主目标）**：任务确实需要数百或上千步，智能体在反馈
   可用时长期保持进展、恢复错误并最终完成任务。
2. **长程规划与时间抽象（机制目标）**：在保持成功率的前提下，一次高层
   决策覆盖更长的真实进展，昂贵高层规划次数明显减少。
3. **长开环预测与执行（诊断目标）**：从一个观测出发，中间不接收新观测，
   连续执行较长动作序列后仍准确到达预测终点。

长开环能力不是长程任务能力的唯一标准。随机性和模型误差存在时，合理系统
可以使用低层反馈纠偏；但如果方法声称具有时间抽象或长尺度世界模型能力，
就必须额外通过固定承诺和开环诊断。

## 3. “很好地解决长程任务”的操作性定义

一个方法只有同时满足以下要求，才能声称很好地解决了长程任务：

1. 任务的 `H*` 足够大，并按 `H*` 而非仅按 `goal_offset` 分层。
2. 与最强基线使用相同的任务、观测频率、反馈机会、动作预算和总模型调用
   预算。
3. 随 `H*` 增长，成功率和 success-horizon AUC 显著优于最强基线，配对置信
   区间支持该结论。
4. 长任务中的局部错误不会不可逆积累；方法能够检测偏离并恢复。
5. 若声称时间抽象，则必须在成功率非劣的情况下显著提高有效承诺长度并减少
   高层规划次数。
6. 若声称多尺度执行，则必须有三个或以上可靠执行尺度进入正式控制，而不是
   只在网络输出中存在、在线策略几乎总选择最短尺度。
7. 结果能够泛化到未见布局、初始状态、视觉变化或动力学变化，而不是只记住
   一个固定环境的可达结构。

“长期正确”不要求每个局部动作永远零错误。应要求任务成功率高、单位时间
不可恢复失败率低、偏离后的恢复率高，以及任务进展不随 episode 长度持续
恶化。

## 4. 当前结果的已知限制

- 原始 LeWM/Flat+TRM 一次规划 5 个模型 block，每个 block 为 5 个环境动作，
  即承诺 25 步后才重新规划。
- 正式 CRAFT 只允许 5/10 步承诺；94.8% 的新规划选择 5 步，平均计划承诺
  约 5.26 步，平均实际执行约 4.84 步。
- unseen-v2 的 1200 个任务中，Flat+TRM 平均每任务规划 1.50 次，CRAFT 为
  3.93 次。当前成功率增益混合了可达性度量、更短世界模型 rollout 和更多
  反馈纠错机会。
- CRAFT 的首达时间分布覆盖较长时间范围，但正式在线控制只执行 5/10 步，
  20/40/80/100 步没有成为正式执行尺度；因此尚未证明多尺度时间抽象。
- Two-Room `offset=100` 成功任务平均约 27 个在线动作完成，在线预算最多为
  50；该条件不是一个必须执行 100 步的任务。

Phase-B gate 在原预注册口径下统计成立，但其科学含义应限定为闭环远期目标
到达结果，不能直接用于更强的长程规划主张。

## 5. 必须完成的公平性控制实验

### 5.1 固定反馈频率矩阵

在完全相同的 paired tasks 上，对 Flat MPC、Flat+TRM 和 CRAFT 分别运行：

| 条件 | 承诺长度 | 主要目的 |
|---|---:|---|
| Fixed-5 | 5 | 比较高频反馈下的目标度量和候选排序 |
| Fixed-10 | 10 | 中等短尺度对照 |
| Fixed-20 | 20 | 检查长 rollout 开始失真的位置 |
| Fixed-25 | 25 | 与原始 LeWM/Flat+TRM 官方控制口径匹配 |
| Fixed-40 | 40 | 强长承诺诊断 |
| Fixed-50 | 50 | 单次规划的完全开环诊断 |
| Adaptive | 5/10/20/25/40 | 检验真实尺度选择和时间抽象 |

至少报告两套严格匹配结果：

1. 所有方法相同承诺长度、相同反馈次数；
2. 所有方法相同总 world-model transition/CEM 预算。

不得只比较 CRAFT@5/10 与 baseline@25 后把差异全部归因于长程表示。

### 5.2 长开环诊断

对每个 `d in {5,10,20,25,40,50}`：

1. 只在起点规划一次；
2. 中途不读取新观测、不重规划；
3. 执行 `d` 步；
4. 记录真实终点、预测终点、目标进展和是否碰撞/停滞。

开环测试是机制诊断，不替代闭环任务成功率。

### 5.3 真正长程的任务矩阵

新增按实际 `H*` 分层的任务，目标至少覆盖：

- `H* = 100, 200, 500, 1000`；
- 多房间或程序化布局；
- 多个必须按顺序完成的子目标；
- 长时间保持、取放、返回或依赖早期状态的任务；
- 扰动后允许恢复但不允许 episode 重置；
- 未见门位置、墙布局、视觉条件和动力学。

真实位置和环境拓扑可用于评测端计算最短路径、任务分层和成功判定，但不得
作为规划器、模型或风险头的输入。

## 6. 必须报告的指标

### 6.1 任务能力

- 每个 `H*`/offset 的成功率及精确置信区间；
- success-horizon 曲线和归一化 AUC；
- 最终真实状态误差；
- time-to-success 的均值、中位数、P90 和超时率；
- SPL 或等价的最短路径归一化效率；
- 每 100 个环境动作的不可恢复失败率；
- 扰动或偏离后的恢复率；
- 顺序子目标完成比例。

### 6.2 时间抽象与规划效率

- 高层规划次数和低层控制更新次数；
- 新观测次数；
- 计划承诺长度与实际执行长度的完整分布；
- 各尺度在新规划中的选择比例，不能使用逐动作重复计数冒充尺度选择次数；
- 每次高层规划带来的真实任务进展；
- 每个成功任务的规划次数和模型调用量。

### 6.3 世界模型与开环可靠性

- 各承诺长度的真实 endpoint error 和 latent endpoint error；
- 预测进展与实际进展的 Pearson/Spearman 相关及置信区间；
- 多步误差随长度的增长曲线；
- conformal endpoint/sequence coverage；
- 失败类型：预测误差、搜索失败、控制失败、停滞和不可恢复偏离。

### 6.4 系统成本

- 总 world-model transitions 和其他模型 forward calls；
- 总墙钟时间、单任务延迟和每成功任务成本；
- GPU 峰值显存、平均利用率和功耗；
- CPU 核数、worker 数、内存和数据读取吞吐。

## 7. 预注册门槛

最终阈值必须在 selection/calibration 阶段冻结，并在打开新 final-test 标签前
写入配置和哈希清单。最低门槛如下。

### 7.1 数据与公平性 gate

- 轨迹级 train/selection/calibration/test 隔离；
- 完全相同的 pair ID、环境 seed、动作预算和成功判定；
- 相同反馈频率的主对照和相同计算预算的补充对照都必须存在；
- final test 只运行一次，不用于选择承诺尺度、阈值或 checkpoint；
- 正式方法不得读取位置、房间 ID、墙、门、路标、模拟器图或测试轨迹答案；
- 所有加载资产和 fallback 分支必须写入逐运行 summary 并接受自动审计。

### 7.2 长程能力 gate

- 在预注册长程集合上相对最强公平基线提升至少 10 个百分点；
- paired-bootstrap 95% 区间下界大于 0；
- 同时报告绝对成功率和随 `H*` 增长的退化斜率/AUC；
- 不能通过增加反馈次数、测试时模型调用或动作预算单独获得该增益。

### 7.3 时间抽象 gate

- 相对相同方法的 Fixed-5 对照，平均有效承诺长度至少达到 15 步；
- 高层规划次数至少减少 30%；
- 成功率非劣界为 -3 个百分点，paired 95% 区间下界不得低于该界；
- 至少三个执行尺度在校准集上通过可靠性检查并进入正式候选集；
- 不能仅依靠一个尺度占绝大多数选择后宣称实现多尺度执行。

### 7.4 执行尺度准入 gate

一个尺度进入正式控制前必须满足：

- 至少 64 个独立 calibration task，而不是把 episode 内帧当独立样本；
- 预测进展与实际进展的相关性置信区间下界大于 0；
- conformal coverage 达到预注册目标；
- endpoint error、停滞率和不可恢复失败率在预注册上限内；
- 在 selection split 上带来有效规划/计算收益。

未通过的尺度只能作为诊断项，不能计入多尺度方法主张。

## 8. 统计和记录要求

- 保留逐 episode JSONL、逐 plan 记录和逐候选诊断；
- 同时保存计划开始时选择的 duration 与每个环境动作所属的 active duration；
  两者不得混合统计；
- 二元成功率使用 paired bootstrap 和精确配对 McNemar；
- 连续指标使用配对 bootstrap，并报告中位数和尾部分位数；
- 多个 seed 保留各自结果，不能把 episode 内多个时间点当独立样本；
- 报告所有失败和超时，不能只统计成功 episode 的效率；
- 优先报告完整 Pareto 曲线，而不是只选择一个最有利的成功率点。

## 9. 推荐执行顺序

1. 在 validation/calibration split 完成 Flat+TRM 与 CRAFT 的 Fixed-5、
   Fixed-25 小规模配对审计，确认反馈频率是否解释主要增益。
2. 完成 CRAFT Fixed-5/10/20/25/40 的 endpoint 与进展可靠性诊断。
3. 只让通过准入 gate 的尺度进入 Adaptive CRAFT。
4. 在新 selection split 冻结尺度、计算预算、非劣界和 checkpoint。
5. 运行完整公平性矩阵，再决定是否打开新的 final test。
6. Two-Room 控制实验通过后，构造 `H* >= 100` 的真正长程任务。
7. 最后运行跨布局、跨环境和跨 backbone 验证。

## 10. 资源隔离与调度规范

用户要求不得影响正在进行的训练任务，因此新实验必须使用独占空闲 GPU；
“显存还有剩余”不等于 GPU 空闲。

启动任何 GPU 实验前必须记录三次间隔采样，并同时满足：

- 目标 GPU 无其他计算进程；
- GPU utilization 持续低于 10%；
- 显存占用低于 2 GiB；
- 温度和功耗处于空闲水平；
- 使用显式 `CUDA_VISIBLE_DEVICES` 或等价设备参数绑定单卡；
- 先运行小规模 smoke，再运行 calibration，最后才运行矩阵；
- 每个阶段可恢复、可分片，禁止一次性抢占所有 GPU。

CPU 实验必须设置明确的线程和 worker 上限。当前训练未结束时，只允许文档、
结果聚合和轻量只读分析；禁止完整 CPU 仿真矩阵和高吞吐数据预处理，以避免
争用内存带宽、page cache 和数据盘 I/O。

- 初始 `nvidia-smi` 查询显示 4 张 NVIDIA RTX A6000 均为 100% GPU
  utilization；随后三次短采样的 SM 利用率仍约为 11%--72%，说明训练持续活跃
  而非空闲；
- 每张卡占用约 39.9/49.1 GiB；
- GPU 2 温度 86°C，其余约 74--75°C；
- 四卡均由同一个 `torchrun --nproc_per_node 4` 训练占用；

测评；也不建议用 CPU 绕过这一限制运行完整矩阵。

## 11. 结果解释模板

每次实验结束后，结论必须明确属于以下哪一级：

- **Level 0：远期目标到达改善**——较大 offset 下闭环成功率提高；
- **Level 1：公平反馈下的长程度量改善**——相同承诺长度和反馈次数下优于基线；
- **Level 2：有效时间抽象**——更长承诺、更少高层规划且成功率非劣；
- **Level 3：真正长程任务能力**——在 `H* >= 100/500/1000` 的任务上保持优势；
- **Level 4：泛化长程能力**——在未见布局、动力学和 backbone 上仍成立。

当前 CRAFT Phase-B 应标为 **Level 0**。只有依次通过公平反馈、时间抽象和
真实长任务 gate 后，才能提升结论级别。
